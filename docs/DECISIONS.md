# Decisions

Format: date, decision, reason.

- 2026-11-03: GLB sources live in `prototipo-assets/` (the docs say `assets/`). Reason: `assets/` would collide with `Assets/` on case-insensitive macOS. Imported copies go to `Assets/_Project/Art/`.
- 2026-11-03: No Git LFS. Reason: `git-lfs` is not installed and the binaries are small (about 5 MB); the user chose to skip it. No `.gitattributes` LFS rules.
- 2026-11-03: Commits stay local on `feature/unity-port`, no pushes, no co-author trailer. Author is the repo git identity. Reason: user instruction.
- 2026-11-03: Simulation assembly (`EchoChamber.Simulation`) has `noEngineReferences`. Data classes are plain `[Serializable]` C# classes; ScriptableObjects in `EchoChamber.Game` only wrap them. Reason: keeps the simulation testable and runnable headless without a scene.
- 2026-11-03: One `EchoChamber.Game` assembly covers `Scripts/Game`, `Scripts/Room` and `Scripts/UI`. Editor tooling is `EchoChamber.Editor`; tests are `EchoChamber.Tests` (EditMode). Reason: fewer cross-assembly references, same separation that matters (Simulation vs presentation).
- 2026-11-03: Input uses the new Input System only (project already has `activeInputHandler: 1`).
- 2026-11-03: Windows build is out of scope tonight: only the macOS Standalone module is installed. The completion build is macOS.
- 2026-11-03: Content is one `GameContent` ScriptableObject (all posts, days, neighbours, places, endings) and one `TuningConfig` ScriptableObject, instead of one asset per post. Reason: fewer assets, same editability, import from docs/data/*.json is one click (`Echo Chamber/Import Content From docs-data`). TuningConfig is only created if missing so inspector edits survive re-imports.
- 2026-11-03: The simulation owns the logical 2D positions and paths of the neighbours (1000x640 world, speed 62/s, crosswalk waits on the pedestrian light). The 3D NeighbourAgent follows the simulated position through WorldMap using a NavMeshAgent. Reason: contagion radii, relation discovery and headless balancing must not depend on the scene.
- 2026-11-03: Enum members use English names (Sens/Com/Ent/Pub/Loc, Anxious/Sceptic/...). Player-facing Portuguese strings (event texts, reaction labels, trait descriptions) live in the Game layer, not in the simulation.
- 2026-11-03: Unity MCP drops during domain reloads. Workflow: write files, `Assets/Refresh`, wait for `unity pipeline list` to show the server reachable, then call MCP tools. Tests run through the `Echo Chamber/Run EditMode Tests` menu item because `unity test` needs the project closed.
- 2026-11-03: The 3D scene keeps the prototype coordinates but mirrors X (`WorldMap.FromProto`, `SceneBuilderUtil.P`), because glTFast mirrors X on import. This keeps the render identical to the prototype (camera looks along -Z, +X to the right of the screen in prototype space).
- 2026-11-03: World-space text (signs, reaction glyphs) uses legacy `TextMesh` with the built-in LegacyRuntime font, and screen UI will use uGUI `Text`. Reason: dynamic font, covers Portuguese accents, no TextMeshPro essentials import needed.
- 2026-11-03: Reaction glyphs are ASCII-safe (`!`, `#`, `+`, `$`, `z`, `..`) instead of the prototype symbols (heart, euro), because the built-in font may lack them.
- 2026-11-03: Unity AI generators report `NoSubscription` in this account, so audio (M7) will be synthesised procedurally in code (WAV generation), not generated with Unity AI.
- 2026-11-03: The scene is built by code (`Echo Chamber/Build Main Scene`, `MainSceneBuilder` + `StreetBuilder`), not hand-placed. Re-running it rebuilds Main.unity from scratch, so manual scene edits must go in the builder.
- 2026-11-03: Play Mode in the background needs `set_run_in_background` + auto tick via the MCP, otherwise frames do not advance while the Editor is unfocused.
- 2026-11-03: Slips are 3D boxes with a world-space uGUI canvas on top (Text/Image), not canvas textures. The print reveal uses a paper-coloured cover that shrinks line by line instead of a clipping plane; the printer body hides the part still inside.
- 2026-11-03: The CRT is a uGUI hierarchy rendered by an orthographic camera into a RenderTexture (`CRTMonitor`), updated at 20 Hz. Neighbours show as neutral dots only.
- 2026-11-03: `DebugTurnBot` plays the game for QA (menu-free). It is not added to the scene by default.
- 2026-11-06: Boss pressure. Failing a day's revenue goal raises `Pressure` by 1 (max 2); meeting it resets to 0. Each level adds `imposedPerLevel` (1) imposed posts to every turn of the next day: high-value sensationalism (60%) or advertising (value >= 0.9), cannot be stamped OCULTAR (forced to NORMAL in `GameSimulation.Publish`). Reason: goals had no consequence and doing nothing (all-normal) ended "Bairro vivo, app em perda" in 100% of seeds. No sixth ending ("Despedido") on purpose: it only makes sense with more days and posts, so it stays for the content-expansion phase. Tuning in `TuningData` (`pressureMax`, `imposedPerLevel`, `imposedSensChance`, `imposedMinValue`).
- 2026-11-06: Stamp ink and silenced authors. The OCULTAR stamp has `hidesPerTurn` (2) uses per turn (`GameSimulation.InkLeft`, enforced in `Publish`: extra hides go out as NORMAL; imposed posts never use ink). Hiding a post makes its author feel silenced: desc +`hiddenAuthorDesc` (0.35), pert -`hiddenAuthorPert` (0.20), applied on delivery. Post authors are now chosen in the simulation (`AuthorOf`, seeded) instead of in `TurnManager`. Reason: all-hide ended "Alive" in 100% of seeds because hiding was free. Values were raised from 0.08/0.05 because a one-neighbour effect barely moves the averages. Result in `docs/BALANCE.md`: all-hide 76% Alive, target-balance 76% Balance. Note: `TuningConfig.asset` keeps its own copy of values; after changing defaults in `TuningData`, update the asset too (the balance report reads the asset).
- 2026-11-06: New visible reaction `Silenciado` (glyph `x`, purple, "ficou calado e zangado"). When a hidden post is delivered, its author gets this reaction for `reactionDuration` (9 s) so the player can see and note the cost of silencing. Noting it does not count towards trait discovery, category patterns or relations (it is caused by the player, not by personality); it is counted in `DiscoveryModel.SilencedNoted`. Reason: the resentment was only two hidden numbers, which breaks "see behaviour, never states". Numbers and endings are unchanged.
- 2026-11-06: "Bairro percebido" now matters. (1) "Equilibrio raro" also needs `endingBalanceUnderstanding` (40%); if the neighbourhood is balanced but understanding is lower, the ending is "Gentrificacao silenciosa" (`GameSimulation.BalanceMissedForUnderstanding` is set, and the final report says so). "Bairro vivo, app em perda" is not gated. (2) The final report adds an epilogue line by tier (`epilogueMid` 35%, `epilogueHigh` 65%, in `Texts.Epilogue`). (3) Headless policies now simulate a diligent player who notes up to `AutoPolicy.NotesPerTurn` (4) reactions per turn; `target-balance-no-notes` never notes. No forecast on the slip: parked in `docs/PROPOSAL_ForecastOnSlip.md`. Calibration: even 1 note per turn gives about 45% understanding, so 40% only stops players who almost never open the notebook; raise `endingBalanceUnderstanding` if it should demand more.
- 2026-11-07: Dilemma posts (point 5). The pool gets about 15 posts whose effects mix opposite directions so the category label no longer predicts the effect (`PostData.dilemma`). Each random slot rolls `dilemmaChance` (50%) to take one, only for categories that have some. Imposed posts never use dilemmas. Drafted by Claude, reviewed by the user before import (`docs/DRAFT_DilemmaPosts.md`). `oracle-per-post` policy decides by real effects as the upper bound for the balance check.
- 2026-11-07: The 15 dilemma posts were approved and imported (post 12 author changed from Seguros Aurora to Seguros Fonseca to avoid two "Aurora" businesses). `oracle-per-post` was retuned to maximise revenue while avoiding clearly harmful posts (amplify unless net effect <= -3, hide at <= -5, all faders 90), because the first version optimised cohesion only and ended "Alive". Result: oracle 84% Balance vs target-balance 52% (criterion: at least +10 points, target-balance between 45% and 70%). `DilemmaPostTests.ReadingEveryPostBeatsTheCategoryRule` guards it. Side effect to watch: all-normal went from 85% to 95% Alive and target-balance now locks the neighbourhood in 16% of runs.
- 2026-11-08: Design pivot to v2 ("Central de Feeds"). Playtest of v1 by the project owner: no clear objective, too much information at once, the tutorial gives away the premise, the notebook and cork board are not needed to win, and amplifying every post without reading wins all goals. Decision: the player now chooses which neighbour's feed each post goes to (instead of stamping amplify/hide), the CRT becomes a wall of live phone feeds (doomscroll), the hidden system is engagement versus polarisation/isolation (TikTok-style), and the game is 5 days with one new thing per day, starting with 3 focal neighbours (Rosa, Armando, Tiago) and growing to 5 (Leonor, Hugo). Full design in `docs/GDD.md` and `docs/GDD_Posts.md`. Reason: v1 ported the three.js prototype rule by rule without a designed player experience. The simulation (utility AI, contagion, NavMesh) is kept.
- 2026-11-08: Removed from the design (code stays until its phase): printer and slips, stamps A/O/N, lever, mixing desk, long newspaper, category colours, ink, tension/cohesion as visible numbers. Kept: control room, phone, CRT (as feed wall), window (starts closed, opens on day 3 as the reveal), cork board (unlocked on day 3), Dr. Valente, new colleague Sara.
- 2026-11-08: Failing never ends the game. Missing the boss target gives a warning; three warnings lead to the "Despedido" ending. Posts have roles (base, trap, bridge, clue, noise). Authors: named neighbours for almost everything, "Anonimo" only for inflamed trap posts, institutions for news and ads. Colleague stays ambiguous (name Sara). Posts start as text; short looping videos are parked for the polish phase. Art bible and day calibration are parked until the game runs. All decided by delegation from the project owner.
- 2026-11-08: `docs/ScopeDocument.md` (D1) describes v1 and was already submitted; it is not edited. `docs/PrototypeSpec.md` and `docs/UnityPortPlan.md` are marked as legacy v1 references.
